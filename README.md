# Турнир CS2 1×1

Готовый сайт для дружеского турнира на 16 игроков:

- четыре GSL-группы по четыре игрока;
- сетка последнего шанса;
- плей-офф и гранд-финал;
- гостевой режим по умолчанию;
- вход организатора по PIN `6996`;
- выбор победителя кнопкой или перетаскиванием;
- выбор карты для каждого матча и стартовых сторон CT/T;
- общий бан/пик шести карт с историей решений и ручным сбросом;
- ручная перестановка стартовых пар в последнем шансе и плей-офф;
- автоматическое продвижение игроков и очистка зависимых результатов;
- призовой пьедестал и итоговые места всех 16 игроков;
- голосование один раз с устройства/сети;
- общие данные для всех гостей и автообновление раз в 10 секунд;
- редактирование названия и имён, сброс сетки и голосов;
- адаптивная версия для компьютера и телефона.

## Быстрый запуск

Нужны Node.js 20.19 или новее и npm.

```bash
npm install
npm run build
```

Для локального API скопируйте `.dev.vars.example` в `.dev.vars`, замените
`SESSION_SECRET` случайной строкой не короче 32 символов и запустите:

```bash
npm run dev
```

Wrangler напечатает локальный адрес. D1 создаётся локально и сохраняется в
`.wrangler/`.

Проверка проекта:

```bash
npm run check
```

## Бесплатный хостинг на Cloudflare Pages

Проект использует Cloudflare Pages Functions и D1. Обычный статический хостинг
покажет интерфейс, но не сможет синхронизировать сетку, безопасно проверять PIN
и хранить общие голоса.

### 1. Создайте базу

В Cloudflare откройте **Storage & databases → D1 SQL database → Create**:

```text
Database name: turnire-setka
```

Таблицы создадутся автоматически при первом запросе сайта. Версионная копия
схемы также лежит в `migrations/0001_initial.sql`.

### 2. Подключите GitHub

Откройте **Workers & Pages → Create application → Pages → Connect to Git**,
выберите репозиторий `felnek1t/TurnireSetka` и укажите:

```text
Project name: turnire-setka
Production branch: main
Framework preset: React (Vite) / Vite
Build command: npm run build
Build output directory: dist
Root directory: оставить пустым
```

Версия Node уже закреплена файлом `.node-version`, поэтому дополнительная
build-переменная не нужна.

### 3. Привяжите D1

После создания Pages-проекта откройте **Settings → Bindings → Add → D1
database**:

```text
Variable name: DB
D1 database: turnire-setka
```

Для Preview лучше создать отдельную базу `turnire-setka-preview`. Не
подключайте preview-сборки к боевой D1, если не хотите, чтобы тестовая ссылка
меняла настоящую сетку.

### 4. Добавьте секреты

В **Settings → Variables and Secrets → Add** создайте для Production две
зашифрованные переменные (`Encrypt`):

```text
ADMIN_PIN=6996
SESSION_SECRET=<случайная строка минимум из 32 символов>
```

Сгенерировать секрет можно локально:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Обязательно создайте новый `SESSION_SECRET`: старое значение из ранее
опубликованного `.env` считается скомпрометированным. PIN `6996` тоже виден в
публичном README и подходит только для игры среди друзей; если ссылку будут
знать посторонние, задайте другой PIN.

Не называйте их `VITE_ADMIN_PIN` или `VITE_SESSION_SECRET`: переменные с
префиксом `VITE_` попадают в публичный браузерный код.

### 5. Перезапустите публикацию

После добавления binding и секретов откройте **Deployments** и нажмите
**Retry deployment / Redeploy** у последнего коммита. Настройки применяются
только к новому deployment. Готовый адрес будет иметь вид
`https://turnire-setka.pages.dev`.

Официальные материалы: [Git integration](https://developers.cloudflare.com/pages/get-started/git-integration/),
[Pages Functions](https://developers.cloudflare.com/pages/functions/),
[D1 bindings](https://developers.cloudflare.com/pages/functions/bindings/),
[D1 migrations](https://developers.cloudflare.com/d1/reference/migrations/).

## Как пользоваться

### Гость

- видит актуальную сетку;
- следит за бан/пиком и видит оставшиеся карты;
- видит призёров и распределение мест вплоть до диапазона 13–16;
- может выбрать игрока в разделе «Кто станет чемпионом?»;
- подтверждает голос один раз;
- после голосования видит свой выбор и общие результаты.

### Организатор

1. Нажмите «Войти».
2. Введите `6996`.
3. В разделе «Бан / пик карт» отмечайте каждую карту как «Бан» или «Пик».
   Решения нумеруются по порядку и сразу видны гостям.
4. При необходимости отмените решение по одной карте. Перед новым выбором
   нажмите «Сбросить бан/пик» и подтвердите ручной сброс.
5. В строке «Карта» нужного матча выберите `de_dust2`, `de_mirage`, `de_overpass`,
   `de_inferno`, `de_nuke` или `de_train`.
6. Возле одного из участников выберите CT или T. Сопернику автоматически
   назначится противоположная сторона.
7. Нажмите кубок у победителя либо перетащите игрока в подходящий следующий
   матч.
8. Когда определится хотя бы один участник последнего шанса или плей-офф,
   нажмите «Перемешать». Перетащите игрока на конкретную верхнюю или нижнюю
   строку соседнего стартового матча. Занятые места поменяются игроками; в
   пустой слот игрок переносится сразу, а будущий участник этого слота
   автоматически появится на освободившемся месте.
9. Изменения сохраняются на сервере автоматически и становятся видны
   гостям.

Карту можно назначить заранее, даже пока участники будущего матча ещё не
определены. Стороны становятся доступны, когда известны оба игрока. Если
поменять ранний результат, сайт предупредит, сколько зависимых результатов и
назначений сторон будет очищено.

Перемешивание работает только между двумя полуфиналами последнего шанса либо
между двумя четвертьфиналами плей-офф. Произвольный перенос в более поздний
раунд не разрешён, потому что он нарушил бы связи победителей и проигравших.
Если переставить уже игравших участников, сайт заранее покажет, сколько
зависимых результатов и сторон CT/T будет очищено. Выбранные карты сохранятся.

После пьедестала показаны остальные итоговые диапазоны: 4–5, 6, 7–8, 9–12 и
13–16. Диапазон означает равное место: дополнительных матчей, разделяющих
игроков внутри такого диапазона, в этой сетке нет.

В «Настройках» можно изменить имена всех 16 игроков, название турнира, начать
сетку заново вместе с картами, сторонами и ручной расстановкой или очистить
голоса. PIN меняется без
пересборки сайта — обновите зашифрованную переменную `ADMIN_PIN` в Cloudflare и
сделайте новый deployment. Общий бан/пик не очищается вместе с сеткой — для
него используется только отдельная кнопка ручного сброса.

## Защита от накрутки

Сервер создаёт атомарную запись голоса с уникальным ключом из HMAC от IP, характеристик устройства и User-Agent. Повторный запрос с тем же ключом отклоняется. Дополнительно на API включены ограничения частоты запросов.

Это разумная защита для дружеского турнира, но не абсолютная идентификация человека: VPN, другое устройство или существенная подмена браузера позволяют обойти ограничение. Для строгого публичного конкурса лучше добавить аккаунты, CAPTCHA или одноразовые коды приглашений.

PIN не попадает в браузерный JavaScript: он проверяется только серверной функцией. После входа сервер выдаёт подписанную `HttpOnly; SameSite=Strict` cookie на 12 часов.

## Структура

```text
src/
  components/        интерфейс сетки, голосования и модальных окон
  data/              стартовые 16 игроков
  lib/bracket.ts     расчёт матчей и продвижения
  lib/mapVeto.ts     действия общего бан/пика карт
  lib/api.ts         запросы к серверу
functions/api/       маршруты Cloudflare Pages Functions
server/              хранение D1, валидация и безопасность
migrations/          схема Cloudflare D1
public/_routes.json  запуск Functions только для /api/*
```

Сервер хранит имена, выбранных победителей, карты, стартовые стороны и голоса.
Все участники следующих раундов, места в группах и пьедестал вычисляются из
результатов — устаревшие или невозможные пары не сохраняются.
